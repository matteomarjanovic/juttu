## Prerequisites

- A [Bluesky](https://bsky.app) account (this will be the article owner)
- Your Bluesky DID (see below for how to find it)
- A stable `site.standard.document` AT URI for each article you want to comment-enable

## Add the snippet

Add the following to your page. The `<link>` and `<script>` tags go in `<head>`; the `<div>` goes in `<body>` where you want comments to appear:

```html
<!-- in <head> -->
<link rel="site.standard.document" href="at://YOUR_DID/site.standard.document/YOUR_GENERATED_TID" />
<script defer src="https://cdn.jsdelivr.net/npm/juttu@latest/juttu-embed.js"></script>

<!-- in <body> -->
<div id="juttu-comments"></div>
```

The comment section resizes itself dynamically — no fixed height required.

## The `<link>` tag (required)

The `<link rel="site.standard.document">` tag tells Juttu which article to show comments for. Its `href` must be a full AT URI in the format:

```
at://YOUR_DID/site.standard.document/YOUR_GENERATED_TID
```

Replace **`YOUR_GENERATED_TID`** with a generated [TID](https://atproto.com/specs/record-key). Generate it once for an article, save it in your page source, and keep reusing that exact same AT URI afterwards.

:::note
If a platform you use (e.g. a Bluesky-native blogging tool) already emits `<link rel="site.standard.document">` tags, no manual configuration is needed.
:::

### Get your `<link>` tag

Enter your Bluesky handle to generate your personalised `<link>` tag:

<HandleResolver />

The helper above generates the complete tag for you, including a fresh TID in the record key.

### Generate a tag in the CLI

If you'd rather generate the tag in your terminal, run:

```sh
npx juttu site-document YOUR_DID
```

Example:

```sh
npx juttu site-document did:plc:abc123
```

That prints a complete `<link rel="site.standard.document" ...>` tag with a valid TID. Run it once per article and keep the generated TID stable.

## The `<script>` tag (required)
The `<script>` tag loads the Juttu embed code. Use `https://cdn.jsdelivr.net/npm/juttu@latest/juttu-embed.js` for the hosted version. Self-hosters should point at their own backend (e.g. `https://comments.example.com/embed/juttu-embed.js`).

### `data-theme` (optional)

Controls the color theme. Accepted values:

| Value | Behavior |
|-------|----------|
| `auto` | Detect the site's theme automatically (default) |
| `light` | Always use the light theme |
| `dark` | Always use the dark theme |

In `auto` mode, Juttu detects whether your site uses a light or dark color scheme by inspecting the inherited text color of the widget container. This means it adapts to your site's actual theme — not the visitor's OS preference.

Example: `data-theme="dark"`

For more advanced theming (custom colors, opaque backgrounds, etc.), see [Customization](/getting-started/customization).

### `data-api-url` (optional)

The URL of the Juttu API backend. Defaults to `https://api.juttu.app`. Self-hosters should set this to their own backend URL:

```html
<script defer src="https://comments.example.com/embed/juttu-embed.js"
  data-api-url="https://comments.example.com"
  data-theme="auto"></script>
```

## The `<div>` tag (required)
The `<div id="juttu-comments">` is where the widget will be rendered. The `id` must be exactly `juttu-comments`.
